# RECIST 1.1 疗效评价系统

一个**单文件、纯前端、零依赖**的肿瘤疗效评价与数据管理工具。按患者录入基线与每次随访的靶病灶径线、非靶病灶状态及新发病灶，自动按 **RECIST 1.1** 规则判定每个时间点的疗效，并生成队列级的疗效分布、ORR / DCR、瀑布图、蜘蛛图与泳道图。

> 打开 HTML 就能用，不需要服务器、不需要安装、不会把任何数据上传到网络。

## 这是做什么的

临床试验或回顾性研究里，每个患者会有一份基线影像和若干次随访影像。要回答的问题往往是：

- 这个患者这一次随访，是 CR / PR / SD 还是 PD？
- 整个队列的 **ORR（客观缓解率）** 和 **DCR（疾病控制率）** 是多少？
- 有多少人缩小、多少人进展？疗效随时间怎么变化？谁进展得早、谁随访得久？

手工在 Excel 里算这一堆百分比和"以历史最小值为参照"的 PD 判定非常容易错。这个工具把这些计算固化成代码，录入即出结果。

## 快速开始

```bash
git clone https://github.com/<your-name>/<your-repo>.git
cd <your-repo>
```

直接用浏览器打开 `index.html` 即可，无需构建、无需安装依赖。也可以起一个本地静态服务：

```bash
# 任选其一
python -m http.server 8000
npx serve .
```

然后访问 `http://localhost:8000`。

第一次使用建议点左下角的 **「载入示例数据」**，会自动创建两位示例患者（非小细胞肺癌 · 试验组；结直肠癌 · 对照组），可以立刻看到完整的判定结果与三张图表。

## 功能特性

**患者与数据管理**

- 患者列表支持姓名/代号、病历号、**肿瘤类型**、**分组**（如 A 组、试验组），后两者可直接在详情页就地修改
- 每个患者一条**基线**记录 + 任意多条**随访**记录
- 基线靶病灶可勾选**是否为淋巴结**，随访时自动继承该属性
- 保存前有 4 秒倒计时的二次确认，防止误覆盖历史数据
- 随访记录支持卡片 / 表格两种视图切换

**自动判定**

- 每录入一次随访，立即给出靶病灶评估、非靶病灶评估、总缓解与**判定依据文本**（例如"靶 CR + 非靶 CR（或无非靶病灶）→ CR"），方便人工复核
- 自动累积**历史最小直径和**，PD 判定以"全过程最小值"为参照，而不是每次都用基线
- 自动识别**新发病灶**：随访出现基线没有且 >0 mm 的病灶，直接判 PD
- 随访中未测量的基线病灶按 0 mm 处理（视为消失），支持"某次漏测"

**队列总览**

- 疗效分布表（CR / PR / SD / 非CR非PD / NE / PD）＋ 占全队列 / 占可评估双口径
- **ORR**、**DCR**、CR 例数、可评估例数四项 KPI，并给出完整计算式
- 按肿瘤类型 / 分组筛选，筛选同时作用于 KPI、分布表、明细表与全部图表
- 逐例明细表，含随访次数、最新肿评结果、首次 PD 时间点

**图表**

- 瀑布图、蜘蛛图、泳道图三张队列图，加单患者的直径总和曲线、各病灶径线变化曲线、时间点反应时间轴
- 所有图表为**手写 SVG**，无任何图表库，点击元素可直接跳转到对应患者
- 瀑布图 / 蜘蛛图支持切换配色维度：按疗效 / 按患者 / 按肿瘤类型 / 按分组

## 图表说明

| 图表                    | 数据口径                                      | 怎么看                                                                |
| --------------------- | ----------------------------------------- | ------------------------------------------------------------------ |
| **瀑布图**               | 每例**最新一次随访**的靶病灶直径和较基线变化（%）               | 默认按数值由大到小排序。向下柱 = 缩小，向上柱 = 增大；柱色可切换为疗效 / 肿瘤类型 / 分组                 |
| **蜘蛛图**               | 每例靶病灶直径和较基线的**百分比变化**随**时间（月）**&#x7684;走势 | 每条线是一个患者，基线统一从 0% 出发；-30% 与 +20% 参考线帮助判断 PR / PD；点击图例可隐藏单条曲线，悬停可高亮 |
| **泳道图（Swimmer Plot）** | 每例一行，横向为自基线起的时间（月）                        | 彩色分段 = 该阶段的疗效状态，竖线 + `PD` 标记首次进展，右端箭头表示末次随访仍未进展；左侧色点代表分组           |
| **直径总和曲线**            | 单患者，每个时间点的靶病灶直径和                          | 点的颜色 = 该时间点的总缓解；含 -30% / +20% 参考线                                  |
| **病灶径线曲线**            | 单患者，每个靶病灶各自的径线                            | 用于观察"哪个病灶在长、哪个在缩"                                                  |
| **反应时间轴**             | 单患者，基线 + 每次随访                             | 每个色块标注该访视的疗效结论与日期                                                  |

## RECIST 1.1 判定规则

工具内部实现的规则（与界面上「查看本工具采用的判定规则」折叠区一致）：

**靶病灶**

- **CR**：所有**非淋巴结**靶病灶完全消失（0 mm）；所有病理性淋巴结（无论靶/非靶）短径须缩小至 **< 10 mm** —— 淋巴结不必完全消失，短径 <10 mm 即视为正常（RECIST 1.1 §3.3）
- **PR**：靶病灶直径和较基线减少 **≥ 30%**
- **PD**：以**研究过程中出现过的最小直径和**为参照，增加 **≥ 20% 且绝对值增加 ≥ 5 mm**（若基线即最小值则以基线为参照）；出现新病灶也视为 PD
- **SD**：缩小未达 PR、增大未达 PD

**淋巴结测量**

- 淋巴结按**短轴**测量
- 短径 **≥ 15 mm** 才可作为靶病灶并计入直径总和
- 短径 **10 – <15 mm** 属非靶病灶
- 短径 **< 10 mm** 视为正常

**非靶病灶**

- 基线只有两种合规状态：**无**（不存在非靶病灶）或**非CR/非PD**（存在、持续）
- 随访：CR = 全部消失且标志物正常、淋巴结短径 <10 mm；非CR/非PD = 持续存在和/或标志物仍高于正常；PD = 明确进展

**总缓解组合**

- 靶 PD / 非靶 PD / 有新病灶 → **总 PD**（优先于其他任何情况）
- 靶 CR + 非靶 CR（或无非靶病灶）→ **CR**
- 靶 CR + 非靶非CR非PD（或不能评估）→ **PR**
- 靶 PR + 非靶非进展 → **PR**
- 靶 SD + 非靶非进展 → **SD**
- 无靶病灶：按非靶病灶单独判定（CR / 非CR非PD / NE）

**其他**

- 靶病灶集合在**基线固定**，随访不可新增靶病灶；随访新出现的病灶属于"新发病灶"，不计入靶病灶总和
- 病灶太小无法测量时：可能已消失记 0 mm；仍存在但模糊无法精确测量默认记 5 mm
- 径线输入精确到 0.1 mm，所有求和统一舍入到 0.1 mm，避免浮点长尾（如 `79.4 + 22.4 = 101.80000000000001`）

## 统计口径

界面展示的疗效与率值统一采用**最新肿评结果**口径，即"按随访日期排序的最后一次随访的总缓解"：

```
可评估例数 N = 有随访结果 且 最新肿评结果 ≠ NE 的患者数
ORR = (CR + PR) / N
DCR = (CR + PR + SD) / N
```

NE 与尚未随访者不计入分母；PD 计入分母但不计入分子。分布表同时给出"占全队列"的比例，便于按全队列口径查阅。

> 程序内部仍会计算 **最佳总缓解（BOR，Best Overall Response）**，但界面不再展示。因此本工具的 ORR / DCR 数值可能与"按最佳总缓解统计"的研究报告不同，对比时请注意口径。

## 数据存储与隐私

- 数据保存在浏览器本地的 **IndexedDB**（库名 `recist-db`，表 `patients` / `visits`），**不经过任何网络传输**，可离线使用
- 因此：**换浏览器、换设备、清理浏览器数据、使用隐私模式都会看不到之前的数据**
- 重要数据请定期用 **「导出 JSON」** 备份
- 若部署在公开的 GitHub Pages 上，页面本身是公开的，但**每个人看到的是自己浏览器里的空数据库**，不会串数据

## 数据结构

导出的 JSON 是 `{ "patients": [...], "visits": [...] }` 结构，字段如下：

```jsonc
// 患者
{
  "id": "m8x2k1-3f9",           // 唯一 ID
  "name": "张三",
  "code": "DEMO-001",            // 病历号（可选）
  "diagnosis": "非小细胞肺癌（IV期）", // 肿瘤类型（可选）
  "group": "试验组",              // 分组（可选）
  "createdAt": 1761091200000
}

// 访视（基线 + 每次随访共用一张表，用 kind 区分）
{
  "id": "m8x2k1-7ab",
  "patientId": "m8x2k1-3f9",
  "kind": "baseline",            // "baseline" | "followup"
  "label": "基线",               // 或 "第1次随访"
  "date": "2026-06-01",          // YYYY-MM-DD
  "lesions": [                   // 靶病灶
    { "name": "右肺上叶结节", "mm": 20, "node": false },
    { "name": "纵隔淋巴结",   "mm": 15, "node": true  }  // node=true 表示淋巴结，mm 为短径
  ],
  "nt": "none",                  // 非靶病灶：none | CR | NCRP | PD | NE
  "newLesion": 0,                // 1 = 存在新发病灶
  "notes": "",
  "createdAt": 1761091200000
}
```

## 导入 / 导出

| 方式      | 位置          | 说明                                                  |
| ------- | ----------- | --------------------------------------------------- |
| 导出 JSON | 患者列表下方      | 全量备份（患者 + 全部访视），可用于迁移或导入其他分析工具                      |
| 导入 JSON | 患者列表下方      | 恢复备份；按 `id` 覆盖同名记录                                  |
| 导出 CSV  | 患者列表下方      | 全队列**逐次访视**明细（含 S0/S1、变化%、历史最小、靶评估、总缓解、判定依据），一行一次访视 |
| 导出 CSV  | 患者详情 · 随访记录 | 单患者随访表，便于贴进论文附表                                     |
| 复制到剪贴板  | 患者详情 · 随访记录 | 以 TSV 复制，可直接粘贴进 Excel                               |

## 部署到 GitHub Pages

仓库里已经是 `index.html`，无需再改文件名：

1. 把本文件夹的内容推到仓库根目录（`index.html`、`README.md`、`LICENSE`）
2. 仓库 → **Settings** → **Pages** → Source 选择 `Deploy from a branch`，分支 `main`、目录 `/ (root)`，保存
3. 等 1–2 分钟，访问 `https://<your-name>.github.io/<your-repo>/`

因为没有任何外部依赖（没有 CDN、没有字体、没有图片），Pages 上可以直接跑，也不会因为网络问题白屏。

## 已知限制

- **单机本地存储**：没有后端、没有账号体系，多人协作需要各自导出 JSON 再合并
- 仅实现 RECIST 1.1 的**解剖学**判定，不含 iRECIST / imRECIST 的免疫治疗确认与"待确认 PD"逻辑
- 不含生存分析（PFS / OS）、随机化、统计检验等
- 病灶按**名称**匹配基线与随访，改名会被当作"基线病灶消失 + 新发病灶"，录入时请保持名称一致
- 淋巴结短径 10–<15 mm 应归为非靶病灶，工具会在基线表单给出提示，但最终归类仍由录入者判断
